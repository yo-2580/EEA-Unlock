# EEA Unlock

כלי שמחיל על מחשב Windows את כללי האזור של **האיחוד האירופי (EEA)**, כך שיכולות ש-Windows פותח רק באירופה (בעקבות חוק ה-DMA) יהיו זמינות גם מחוץ לה. הכלי הפיך בכל רגע, כולל שחזור אוטומטי אם משהו משתבש.

הכלי קיים בשתי גרסאות, עם אותה לוגיקה: **ממשק גרפי בפייתון** וגרסת **PowerShell**.

> **הערה:** הפרויקט אינו קשור למיקרוסופט. הוא משנה קובץ מערכת מוגן. השימוש באחריותך בלבד.

## איך זה עובד

Windows שומר בקובץ

```
C:\Windows\System32\IntegratedServicesRegionPolicySet.json
```

רשימה של כללים (`policies`). לכל כלל יש מצב ברירת מחדל (`defaultState`) ותנאי אזור (`conditions.region`) עם רשימות מדינות, `enabled` או `disabled`. כמה מהכללים האלה נקבעים לפי האזור של המחשב, ובחלקם הרשימה היא מדינות ה-EEA.

הכלי:

1. **מזהה את האזור של המחשב.** הוא קורא את `DeviceRegion` ב-HKLM (שעליו Windows מסתמך בפועל), את האזור של המשתמש הנוכחי ואת האזור של `HKU\.DEFAULT`. אפשר להוסיף אזורים ידנית.
2. **מוצא כללי EEA.** כל רשימה שמכילה לפחות 5 מדינות EEA נחשבת רשימת EEA. רשימות של מדינות אחרות (סין, רוסיה, ארה"ב ועוד) לא נוגעים בהן.
3. **מוסיף את האזור שלך** לכל רשימה כזאת שנבחרה, ואם האזור מופיע ברשימה ההפוכה של אותו כלל הוא מוסר משם כדי שלא תהיה סתירה.
4. **כותב את הקובץ בבטחה.** הוא מגבה את המקור, לוקח בעלות זמנית, כותב, בודק שה-JSON תקין, ומחזיר את הבעלות ל-TrustedInstaller.

## התקנה והרצה

### דרישות כלליות

- Windows 10 או 11 שבהם קיים הקובץ `IntegratedServicesRegionPolicySet.json`
- הרשאות מנהל (שתי הגרסאות מבקשות אותן בעצמן)

### ממשק גרפי (Python)

1. מתקינים את PyQt6:

   ```
   pip install PyQt6
   ```

2. מריצים:

   ```
   python eea_unlock_gui.py
   ```

3. מאשרים את בקשת ההרשאות (UAC). החלון נפתח מחדש כמנהל.
4. בעמוד **ראשי** בוחרים "מומלץ" או "מלא", לוחצים "הפעל", ומפעילים מחדש את המחשב.

**מה יש בחלון**

| עמוד | תוכן |
|---|---|
| ראשי | סטטוס (כבוי, פעיל, או "Windows חזר להגדרות המקור"), בחירה בין "מומלץ" ל"מלא", כפתור הפעלה או עדכון, וכפתור ביטול. המדינה מזוהה אוטומטית, ואם לא זוהתה אפשר להקליד קוד |
| כל התכונות | כל הכללים בעברית פשוטה, מקובצים לפי קבוצות, עם חיפוש וסינון. לכל שורה יש הסבר, סימון "מתועד" או "לפי השם", וסימון "מוחל כרגע". אפשר לסמן כל כלל בנפרד |
| אבחון ויומן | יומן הפעולות והשגיאות, כפתורים לפתיחה והעתקה, ומידע טכני |
| עזרה ומקורות | הסבר קצר על הכלי ורשימת מקורות |

**תקלות בהפעלה:** אם החלון לא נפתח, מריצים `python eea_unlock_gui.py --debug` משורת פקודה כדי לראות שגיאות. שגיאות הפעלה נשמרות גם ביומן (ראו [יומן שגיאות](#יומן-שגיאות)).

### PowerShell

1. מורידים את `EEA-Unlock.ps1` ואת `EEA-Unlock.cmd` **לאותה תיקייה**.
2. לוחצים פעמיים על `EEA-Unlock.cmd`.
3. מאשרים את בקשת ההרשאות.
4. בתפריט מתחילים מ-**2 (תצוגה בלבד)** או **7 (תצוגה, הקלות בלבד)**, ורק אחרי שבדקתם מה ישתנה בוחרים החלה.
5. מפעילים מחדש את המחשב.

תפריט הסקריפט:

| בחירה | פעולה |
|---|---|
| 1 | החלה מלאה (הקלות והחמרות של אירופה) |
| 2 | תצוגה בלבד |
| 3 | שחזור למצב הקודם |
| 4 | מצב נוכחי |
| 5 | אבחון |
| 6 | החלה, הקלות בלבד |
| 7 | תצוגה, הקלות בלבד |

אפשר גם להריץ ישירות:

```powershell
powershell -ExecutionPolicy Bypass -File .\EEA-Unlock.ps1 -DryRun
```

| פרמטר | משמעות |
|---|---|
| `-Apply` | החלה מלאה |
| `-BenefitsOnly` | החלה (או תצוגה, עם `-DryRun`) של הקלות בלבד |
| `-DryRun` | תצוגה בלבד, בלי שינוי |
| `-Restore` | שחזור למצב הקודם |
| `-Status` | מצב נוכחי |
| `-Diagnose` | אבחון: אילו אזורים זוהו ומה מצב כללי ה-EEA בקובץ |
| `-Region IL,US` | קודי אזור נוספים (מתווספים לאלה שזוהו אוטומטית) |
| `-SkipDisabledFor` | לא נוגע בכל רשימות ה-`disabled` |
| `-Force` | שחזור גם כשהקובץ השתנה מאז ההחלה |
| `-NoPause` | בלי המתנה בסוף ההרצה |

כל הרצה ללא פרמטרים פותחת את התפריט.

## מצבי הפעלה

### מומלץ (יתרונות בלבד)

בקובץ יש כללי `disabled` שהם דווקא לטובת המשתמש (פחות פרסומות ואיסוף נתונים), וכללי `enabled` שמגבילים. לכן הכלי כולל **רשימת הקלות** לפי GUID של כל כלל, ובמצב הזה מחיל רק עליהם. כל כלל שלא ברשימה, כולל כללים חדשים שיתווספו בגרסאות עתידיות, לא נוגעים בו.

בגרסה הגרפית זה המצב "מומלץ". ב-PowerShell זה מצב `-BenefitsOnly` (תפריט 6 ו-7).

### מלא (בדיוק כמו באירופה)

האזור שלך מתווסף לכל רשימות ה-EEA, כך שהמחשב מתנהג בדיוק כמו מחשב אירופי. זה כולל **גם תכונות ש-Windows מכבה באירופה**, כמו Copilot.

### בחירה אישית (בגרסה הגרפית בלבד)

בעמוד "כל התכונות" אפשר לסמן כל כלל בנפרד. אם הבחירה אינה זהה ל"מומלץ" או ל"מלא", הסטטוס יציג "מותאם אישית".

> הסיווג של הכללים (הקלה, פחות פרסומות ומעקב, תכונה שנכבית, לא ברור) מבוסס בחלקו על מקורות ברשת ובחלקו על שמות הכללים בלבד. מיקרוסופט לא מתעדת את הכללים, ולכן חלק מהסיווג הוא פרשנות ולא עובדה. בגרסה הגרפית כל שורה מסומנת "מתועד" או "לפי השם" כדי שיהיה ברור.

## שחזור ובטיחות

| שכבה | Python | PowerShell |
|---|---|---|
| גיבוי מאומת: המקור נשמר ב-`%ProgramData%\EEAUnlock`, עם חתימת SHA256 שנבדקת לפני כל שחזור | כן | כן |
| כתיבה בטוחה: אחרי הכתיבה הקובץ נבדק, ואם אינו JSON תקין הוא חוזר מיד למצב הקודם | כן | כן |
| אימות אחרי כתיבה: הכלי קורא את הקובץ מחדש ובודק שכל הכללים שנבחרו נקלטו, ואם לא הוא מחזיר את המצב הקודם | כן | לא |
| `Restore.cmd`: קובץ שחזור עצמאי שנוצר בכל החלה ועובד גם בלי הכלי ובלי Python או PowerShell | כן | כן |
| שחזור הפוך: אם הגיבוי אבד, הכלי מסיר את האזורים מהכללים | כן | כן |
| מוצא אחרון: `sfc /scannow` או `DISM /Online /Cleanup-Image /RestoreHealth` מחזירים קבצי מערכת למקור | כן | כן |

הרצה חוזרת לא מצטברת: הכלי תמיד מחשב מחדש מהמקור הנקי, כך שאפשר לעבור בין "מומלץ" ל"מלא" ולהחליף אזור בלי להשאיר שאריות.

כדי להסיר לגמרי: מריצים שחזור, ואחר כך מוחקים את התיקייה `%ProgramData%\EEAUnlock`.

## יומן שגיאות

הגרסה הגרפית שומרת יומן קבוע בקובץ:

```
%ProgramData%\EEAUnlock\eea_unlock.log
```

ואם אי אפשר לכתוב שם, ב-`%TEMP%\eea_unlock.log`. כשהקובץ עובר 1MB הוא מסתובב לקובץ `.1`.

**מה נרשם**

- כל פעולה (הפעלה, שחזור) והתוצאה שלה.
- שגיאות בהפעלה או בשחזור: סוג השגיאה, הקשר (אזורים, כמה כללים נבחרו, הרשאות מנהל, מצב הגיבוי, גודל הקבצים והאם הם לקריאה בלבד) ו-traceback מלא.
- כשלים בפקודות המערכת `takeown` ו-`icacls`, עם הפלט שלהן.
- כשל ביצירת הגיבוי, ואימות שנכשל אחרי כתיבה.
- שגיאות הפעלה של התוכנה.

**איך ניגשים אליו:** בעמוד "אבחון ויומן" יש כפתורים לפתיחת הקובץ והתיקייה ולהעתקת היומן ללוח. כשפעולה נכשלת מופיעה הודעה עם "פתח יומן" ו"העתק פרטים", ופס אדום בעמוד הראשי עד לפעולה מוצלחת הבאה. בדיווח על תקלה כדאי לצרף את הקטע האחרון מהיומן.

בגרסת PowerShell אין יומן בקובץ, והשגיאות מוצגות בקונסול.

**להוסיף כלל לסיווג:**

- בגרסה הגרפית: מוסיפים את ה-GUID שלו לטבלה `CATALOG` בראש הקובץ, עם קטגוריה, כותרת, הסבר וסימון אם הוא מתועד.
- ב-PowerShell: מוסיפים את ה-GUID (באותיות קטנות, בסוגריים מסולסלים) לטבלה `$BenefitGuids` בראש הסקריפט.

כללים שלא מופיעים בסיווג מוצגים בגרסה הגרפית כ"כללים חדשים שהכלי לא מכיר" ולא מסומנים כברירת מחדל.

## מגבלות ידועות

- **עדכוני Windows:** עדכון גדול עלול להחזיר את הקובץ למקור. הגרסה הגרפית מציגה אז "Windows חזר להגדרות המקור", ומפעילים שוב.
- **תכונות תלויות גרסה:** הוספת אזור לקובץ אינה מבטיחה שהתכונה תפעל. חלק מהתכונות תלויות גם בגרסת ה-Windows, בחשבון המשתמש ובהפעלה הדרגתית של מיקרוסופט.
- **אין אישור שזה פועל מחוץ לאירופה:** המקורות מלמדים שהאפשרויות האלה נבנו עבור אירופה, אבל לא מצאנו מקור שמאשר שהוספת מדינה לקובץ מפעילה אותן בפועל מחוץ לאזור. לכן כדאי להתחיל ב"מומלץ" ולבדוק מה באמת השתנה.
- **חסימה מחוץ לקובץ:** ייתכן שחלק מהמגבלות אינן בקובץ הזה בכלל. אבחון (בכל גרסה) מראה מה מצב הקובץ.
- **שינוי שמות:** בגרסאות שונות של Windows הרשימות נקראות `enabled`/`disabled` או `enabledFor`/`disabledFor`. הכלי מזהה את שני הסוגים.
- **מקורות ישנים:** רוב המקורות שעליהם מבוסס הסיווג הם מ-2023 עד 2025, ומיקרוסופט משנה את ההתנהגות כל הזמן.
- **מצב הבדיקות:** הלוגיקה של עיבוד הקובץ, השחזור וההחלה נבדקה על קבצי JSON לדוגמה במבנה של הקובץ האמיתי, בשתי הגרסאות. הממשק הגרפי נבדק בסביבת בדיקה ללא Windows. ההפעלה על Windows אמיתי (בעלות על הקובץ, קריאת האזור מהרישום, הפעלה מחדש) נבדקה פחות. מומלץ להתחיל בתצוגה בלבד, ותקלות אפשר לדווח ב-Issues.
- **שימוש עם HaFeed:** אם משתמשים גם ב-HaFeed, שניהם כותבים לאותו קובץ. אפשר להריץ אותם בכל סדר, אבל הסרת HaFeed עלולה להחזיר את הקובץ לגרסה שלפני ההחלה, ואז מריצים את הכלי מחדש.
