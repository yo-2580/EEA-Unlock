# EEA Unlock

סקריפט PowerShell שמחיל על מחשב Windows את כללי האזור של **האיחוד האירופי (EEA)**, כך שיכולות ש-Windows פותח רק באירופה (בעקבות חוק ה-DMA) יהיו זמינות גם מחוץ לה. הסקריפט הפיך בכל רגע, כולל שחזור אוטומטי אם משהו משתבש.

> **הערה:** הפרויקט אינו קשור למיקרוסופט. הוא משנה קובץ מערכת מוגן. השימוש באחריותך בלבד.

## איך זה עובד

Windows שומר בקובץ

```
C:\Windows\System32\IntegratedServicesRegionPolicySet.json
```

רשימה של כללים (`policies`). לכל כלל יש מצב ברירת מחדל (`defaultState`) ותנאי אזור (`conditions.region`) עם רשימות מדינות, `enabled` או `disabled`. כמה מהכללים האלה נקבעים לפי האזור של המחשב, ובחלקם הרשימה היא מדינות ה-EEA.

הסקריפט:

1. **מזהה את האזור של המחשב.** הוא קורא את `DeviceRegion` ב-HKLM (שעליו Windows מסתמך בפועל), את האזור של המשתמש הנוכחי ואת האזור של `HKU\.DEFAULT`. אפשר להוסיף אזורים ידנית עם `-Region`.
2. **מוצא כללי EEA.** כל רשימה שמכילה לפחות 5 מדינות EEA נחשבת רשימת EEA. רשימות של מדינות אחרות (סין, רוסיה, ארה"ב ועוד) לא נוגעים בהן.
3. **מוסיף את האזור שלך** לכל רשימה כזאת, ואם האזור מופיע ברשימה ההפוכה של אותו כלל הוא מוסר משם כדי שלא תהיה סתירה.
4. **כותב את הקובץ בבטחה.** הוא מגבה את המקור, לוקח בעלות זמנית, כותב, בודק שה-JSON תקין, ומחזיר את הבעלות ל-TrustedInstaller.

## דרישות

- Windows 10 או 11 שבהם קיים הקובץ `IntegratedServicesRegionPolicySet.json`
- PowerShell 5.1 ומעלה (מובנה ב-Windows)
- הרשאות מנהל (הסקריפט מבקש אותן בעצמו)

## התקנה והרצה

1. מורידים את `EEA-Unlock.ps1` ואת `EEA-Unlock.cmd` **לאותה תיקייה**.
2. לוחצים פעמיים על `EEA-Unlock.cmd`.
3. מאשרים את בקשת ההרשאות.
4. בתפריט מתחילים מ-**2 (תצוגה בלבד)** או **7 (תצוגה – הקלות בלבד)**, ורק אחרי שבדקתם מה ישתנה בוחרים החלה.
5. מפעילים מחדש את המחשב.

תפריט הסקריפט:

| בחירה | פעולה |
|---|---|
| 1 | החלה מלאה (הקלות והחמרות של אירופה) |
| 2 | תצוגה בלבד |
| 3 | שחזור למצב הקודם |
| 4 | מצב נוכחי |
| 5 | אבחון |
| 6 | החלה, הקלות בלבד |
| 7 | תצוגה, הקלות בלבד |

אפשר גם להריץ ישירות:

```powershell
powershell -ExecutionPolicy Bypass -File .\EEA-Unlock.ps1 -DryRun
```

## מצבי הפעלה

### החלה מלאה
האזור שלך מתווסף לכל רשימות ה-EEA, כך שהמחשב מתנהג בדיוק כמו מחשב אירופי. זה כולל **גם תכונות ש-Windows מכבה באירופה**, כמו Copilot.

### הקלות בלבד (`-BenefitsOnly`)
בקובץ יש כללים `disabled` שהם דווקא לטובת המשתמש (פחות פרסומות ואיסוף נתונים), וכללי `enabled` שמגבילים. לכן הסקריפט כולל **רשימת הקלות** לפי GUID של כל כלל, ובמצב הזה מחיל רק עליהם. כל כלל שלא ברשימה, כולל כללים חדשים שיתווספו בגרסאות עתידיות, מדולג ומוצג תחת "דולגו".

> הסיווג מבוסס על שמות הכללים בלבד. מיקרוסופט לא מתעדת אותם, ולכן הסיווג הוא פרשנות ולא עובדה.

## פרמטרים

| פרמטר | משמעות |
|---|---|
| `-Apply` | החלה מלאה |
| `-BenefitsOnly` | החלה (או תצוגה, עם `-DryRun`) של הקלות בלבד |
| `-DryRun` | תצוגה בלבד, בלי שינוי |
| `-Restore` | שחזור למצב הקודם |
| `-Status` | מצב נוכחי |
| `-Diagnose` | אבחון: אילו אזורים זוהו ומה מצב כללי ה-EEA בקובץ |
| `-Region IL,US` | קודי אזור נוספים (מתווספים לאלה שזוהו אוטומטית) |
| `-SkipDisabledFor` | לא נוגע בכל רשימות ה-`disabled` |
| `-Force` | שחזור גם כשהקובץ השתנה מאז ההחלה |
| `-NoPause` | בלי המתנה בסוף ההרצה |

כל ההרצות ללא פרמטרים פותחות את התפריט.

## שחזור ובטיחות

| שכבה | מה היא עושה |
|---|---|
| גיבוי מאומת | המקור נשמר ב-`%ProgramData%\EEAUnlock`, עם חתימת SHA256 שנבדקת לפני כל שחזור |
| כתיבה בטוחה | אחרי הכתיבה הקובץ נבדק, ואם אינו JSON תקין הוא חוזר מיד למצב הקודם |
| `Restore.cmd` | קובץ שחזור עצמאי שנוצר בכל החלה ועובד גם בלי הסקריפט ובלי PowerShell |
| שחזור הפוך | אם הגיבוי אבד, הסקריפט מסיר את האזורים מהכללים |
| מוצא אחרון | `sfc /scannow` או `DISM /Online /Cleanup-Image /RestoreHealth` מחזירים קבצי מערכת למקור |

הרצה חוזרת לא מצטברת: הסקריפט תמיד מחשב מחדש מהמקור הנקי, כך שאפשר לעבור בין "מלא" ל"הקלות בלבד" ולהחליף אזור בלי להשאיר שאריות.

כדי להסיר לגמרי: מריצים שחזור, ואחר כך מוחקים את התיקייה `%ProgramData%\EEAUnlock`.

## מה משתנה בפועל

הרשימה מתבססת על קובץ מדיניות של Windows 11 25H2. בגרסאות אחרות יכולים להיות כללים שונים.

<details>
<summary><b>הקלות שנפתחות</b> (נכללות ב-<code>-BenefitsOnly</code>)</summary>

- הסרת Edge מותרת, ואפשרות לכבות חיפוש ברשת
- הגדרת אפליקציות ברירת מחדל מורחבת: סוגי קבצים נוספים, PDF בלחיצה אחת, הצמדה
- ספקי חיפוש של צד שלישי, ותוכן מודגש של צד שלישי בחיפוש
- ספק של צד שלישי ברשימת החיפושים האחרונים
- צד שלישי יכול להתאים את הדגשת החיפוש בשורת המשימות
- הבחנה בין רכיבי מערכת לאפליקציות
- פיד של צד שלישי בלוח הווידג'טים, ואפשרות לכבות את הפיד של מיקרוסופט
- קישורי ווידג'טים נפתחים בדפדפן ברירת המחדל
- ווידג'טים במסך הנעילה
- אפשר להסיר את StartExperiencesApp ואת Microsoft Store
- שיתוף דרך כל ספקי השיתוף
- עדכון מזורז לאפליקציות צד שלישי
- מסכי פרטיות עם אפשרויות לא מוטות
- פתיחות לספקי צ'אט של צד שלישי ב-Copilot

</details>

<details>
<summary><b>פחות פרסומות, מעקב ואיסוף נתונים</b> (נכללות ב-<code>-BenefitsOnly</code>)</summary>

אלה כללי `disabled` שמיקרוסופט מכבה באירופה, וכיבוים לטובת המשתמש:

- פחות המלצות אתרים בתפריט התחל
- פחות מסכי פרסום ועמודי פרסום בתהליכי הגדרה
- פחות קידום והפעלה ישירה של Edge, ופחות מיקוד קמפיינים
- פחות הצעות לרכישת מוצרי מיקרוסופט בהגדרות (דרך Bing)
- פחות הצעות גיבוי ל-OneDrive
- Copilot לא מוצמד אוטומטית בעדכונים
- אפליקציות מיקרוסופט לא ניגשות למזהי פרופיל בדפדפן
- פחות שיתוף נתוני ביצועים של Xbox, ואירועי טלמטריה מסומנים כמוגבלים

</details>

<details>
<summary><b>תכונות שיורדות</b> (מוחלות רק ב"החלה מלאה")</summary>

- Windows Copilot, והקשר מסך (OCR) ב-Copilot
- חוויית מסך מלא של Xbox
- כניסה אוטומטית לאפליקציות
- Narrator scripting extensions
- OneDrive Resume
- Phone Link בתפריט התחל
- WinAct: שעון ויומן
- הצגת Widgets כאפליקציית סטטוס במסך הנעילה
- התראות ווידג'טים בשורת המשימות ותגים של ווידג'טים של צד שלישי
- אינטגרציית שורת המשימות של ווידג'טי מיקרוסופט
- כניסה לווידג'ט מוגבלת לחשבון ברירת המחדל, וווידג'טים מוגבלים להמלצות סטטיות
- הגבלת שיתוף נתונים של ווידג'טים (כולל של צד שלישי)
- אפשרויות גיבוי מוגבלות, וגיבוי לארגונים
- קבצי Office אחרונים בהמלצות, תוכן גרף ב-File Explorer, פעולות מומלצות ב-Explorer ובשולחן העבודה
- חיפוש מיקרוסופט מובנה ב-File Explorer, וחיפושים אחרונים ברשת

</details>

<details>
<summary><b>לא ברור או אין השפעה</b> (לא נכללים ב-<code>-BenefitsOnly</code>)</summary>

- כללים שבהם ברירת המחדל ורשימת ה-EEA זהות, כמו `File Explorer Search is third party extensible`
- כללים שהשם שלהם אינו חד-משמעי: `Edge is required for web search`, `Replace tailored experience with personalized offers`, `A9 Optional Component`, `Manage Vega search`, `Manage Recall Data Provision Dialog`, `EEA Region check for default behavior tampering in Registry`
- כללים נוספים שלא סווגו, כמו UQI, SearchV2, Windows Account Sync Consent ו-Copilot hardware key

</details>

כדי להוסיף כלל להקלות, מוסיפים את ה-GUID שלו (באותיות קטנות, בסוגריים מסולסלים) לטבלה `$BenefitGuids` בראש הסקריפט.

## מגבלות ידועות

- **עדכוני Windows:** עדכון גדול עלול להחזיר את הקובץ למקור. במקרה כזה מריצים את הסקריפט שוב.
- **תכונות תלויות גרסה:** הוספת אזור לקובץ אינה מבטיחה שהתכונה תפעל. חלק מהתכונות תלויות גם בגרסת ה-Windows, בחשבון המשתמש ובהפעלה הדרגתית של מיקרוסופט.
- **חסימה מחוץ לקובץ:** ייתכן שחלק מהמגבלות אינן בקובץ הזה בכלל. הרצת `-Diagnose` מראה אם הקובץ מעודכן.
- **שינוי שמות:** בגרסאות שונות של Windows הרשימות נקראות `enabled`/`disabled` או `enabledFor`/`disabledFor`. הסקריפט מזהה את שני הסוגים.
- **מצב הבדיקות:** הלוגיקה של עיבוד הקובץ והשחזור נבדקה על קבצי JSON לדוגמה במבנה של הקובץ האמיתי. ההפעלה על Windows (בעלות על הקובץ, קריאת האזור מהרישום) נבדקה פחות. מומלץ להתחיל ב-`-DryRun`, ותקלות אפשר לדווח ב-Issues.
- **שימוש עם HaFeed:** אם משתמשים גם ב-HaFeed, שניהם כותבים לאותו קובץ. אפשר להריץ אותם בכל סדר, אבל הסרת HaFeed עלולה להחזיר את הקובץ לגרסה שלפני ההחלה, ואז מריצים את הסקריפט מחדש.
